# Library organization

Group modules by the feature that owns their behavior. Keep tests beside the
modules they exercise and import concrete files; there is no root or feature
barrel that mixes browser-safe contracts with server operations.

| Folder | Owns |
| --- | --- |
| `arena/` | Are.na contracts, reader data and server integration |
| `body/` | BODY composition, health summaries, threshold events and export consent |
| `context/` | Context contracts, replay and XR context adapters |
| `evidence/` | Private evidence ingestion, recovery, review and signal processing |
| `files/` | Bounded selected-file reading |
| `http/` | Request and local-origin policy |
| `music/` | Spotify, Last.fm, playlist and local audio operations |
| `native/` | Native receiver, pairing, transfer and delivery lifecycle |
| `privacy/` | Cross-feature browser and private-data boundary tests |
| `research/` | Research catalogue, Dramaturg, Linz and experimental adapters |
| `studio/` | Studio schema, demo, correlation, Atlas, scenarios and Director |
| `validation/` | Server-side private validator bridge |
| `vault/` | Encrypted storage, sessions, authentication and access policy |
| `xr/` | Spatial projections, journey, archive and scene behavior |

## TypeScript conventions

- Use `.ts` for non-JSX modules and `.tsx` only where JSX is needed. Ambient
  declarations use `.d.ts`; `vault/sql-js.d.ts` describes the Vault dependency.
- Keep kebab-case filenames and colocate `*.test.ts` with their implementation.
  Keep feature-specific types with their owner; use `import type` for type-only
  dependencies instead of a catch-all types directory.
- Use `./sibling` within a folder and `@/lib/<feature>/<file>` across features.
  Standalone command-line scripts use relative paths to concrete modules.
- Folder ownership does not imply browser safety. Preserve server-only imports,
  existing runtime guards and the browser-boundary tests. Never import storage,
  credentials or validator execution into a client component.
- Keep shared policy in its owning feature. Add another shared helper only when
  callers share a concrete responsibility; avoid a miscellaneous utilities folder.

## Generated contracts and fictional fixtures

Python remains the source for the Context, native transfer, BODY review and health
event contracts. Regenerate them from the repository root:

```sh
PYTHONPATH=research/rehearsal-dramaturg research/rehearsal-dramaturg/.venv/bin/python research/rehearsal-dramaturg/scripts/contracts.py
```

The generator writes into `context/`, `native/` and `body/`. Do not edit generated
contracts independently. The public `body/body-preview.fictional.json` sample is
generated by `research/rehearsal-dramaturg/scripts/body_preview.py`; it asserts
fictional, simulated observations before writing. Keep real evidence and exports
outside this tree.

This reorganization preserves the PR remediation behavior: historical staging
and acceptance are separate from export consent, timestamp validation preserves
source values, and passphrases remain restricted to supported Vault actions.
